# 图片上传：节点 12

用户确认：仅支持 JPEG、PNG，保留静态 URL 公开访问，不增加读取鉴权。本阶段不需要真实题目图片，测试均在临时目录生成。

## 接口与限制

`POST /api/v1/uploads/images`，multipart/form-data 字段名 `file`；仅教师/管理员可上传，未登录 401，学生 403。成功仍为 200，响应保留 `{ "url": "http://localhost:8000/uploads/images/<random>.png" }` 结构，以 PUBLIC_BASE_URL 的配置为准。

| 项目 | 规则 |
| --- | --- |
| MIME | 仅 image/jpeg、image/png；其他类型 415 |
| 文件内容 | 必须实际解码为匹配声明的 JPEG/PNG；伪装、损坏、空文件 400 |
| 动画 | 不支持 GIF/WebP，也不支持多帧 APNG；动态 PNG 返回 400 |
| 字节上限 | 输入和重新编码后的输出均最多 5 MiB，即 5 × 1024 × 1024 字节；超限 413 |
| 像素限制 | 宽、高各最多 10,000，总像素最多 20,000,000；超限 413，不自动缩小 |
| 文件名 | 服务端随机 UUID，加校验后的 .jpg/.png 后缀，不使用原始文件名或路径 |
| 存储失败 | 503，响应不透露本机路径；仅清理本次创建的残留文件，不覆盖已有文件 |

新服务 app/services/images.py 分块读取上传文件，每块最多 64 KiB，累计最多读取上限加 1 字节便停止；框架提供的文件大小只用于提前拒绝，不能替代实际读取限制。接口 finally 关闭上传文件，图片解码与写盘在工作线程执行。

使用 Pillow 限定 JPEG/PNG 解析器，先检查格式和尺寸、verify，再重新打开并完整 load，避免仅凭文件头接受损坏图片。新依赖锁定到 Pillow 12.3.0；只新增这一依赖，没有升级已有包。实现参考 [Pillow 安全说明](https://pillow.readthedocs.io/en/stable/handbook/security.html)，不宣称消除了图片解析库的全部风险。

## 重新编码与文件保存

只处理新上传文件：按 EXIF 方向调整像素后，从干净像素创建新图再编码，移除 EXIF、注释、色彩配置等元数据和尾随内容。JPEG 转 RGB、quality=90；PNG 转 8 位 RGBA 并保留透明度。图片字节、文件大小及部分色彩/精度可能变化，JPEG 不保证无损；超出输出大小限制返回 413。

校验和编码通过后才写入 uploads/images，采用排他创建，发生文件名碰撞也不覆盖旧文件。写入成功才返回 URL；写失败会尝试删除本次部分文件，清理失败记录日志。进程崩溃、断电等仍可能留下残留，不承诺事务式文件存储或自动定期清理。

当前配置目录应由服务进程和可信维护者控制，不允许不可信本机用户置换目录或植入符号链接。原有上传文件、旧 URL 和题目引用不自动重写、删除或重新审查；没有图片删除/替换入口。

## 公开访问边界

GET /uploads/... 保持匿名静态读取。知道 URL 就可以访问，随机文件名不是权限控制；归档作业不会使图片 URL 失效。不要上传保密试题、个人信息或不适合公开的图片。旧文件也仍可能通过原 URL 访问。

题目 image_urls 仍接受上传后的 URL，本节点不增加远程图片下载或外部 URL 审查，也不为作业快照复制图片二进制内容。

FastAPI/Starlette 会先解析 multipart 并可能将文件暂存磁盘，路由的分块读取限制**不是整个 HTTP 请求体的网络入口上限**。正式部署还需要网关请求体限制、并发/频率限制、超时、磁盘配额和监控；2,000 万像素解码仍会占用可观内存，工作线程也不是资源隔离沙箱。
