# 后台批改串联验收（14d）

2026-09-11 完成。新增两项真实 TCP/HTTP 串联测试，连同 25 项直接关联回归，`27 passed in 19.64s`，使用 `-W error`；Ruff 通过。本轮没有修改业务代码、依赖或索引，也没有执行全套测试。

## 覆盖流程

### 自动重试、人工重试与查分

管理员引导后，教师/学生账号、建班入班、两道虚构简答题、草稿发布和答案提交全部通过 HTTP 完成。仅管理员初始化使用测试数据库写入。

1. 不启动 worker，提交仍返回 201，教师看到 pending、执行次数 0，学生可查询已保存的答案。
2. 测试 provider 每轮第一题成功、第二题抛出临时错误。实际等待 1 秒、2 秒退避后，三次预算耗尽为 failed。
3. 两题草稿始终为空，不留下第一题的部分评分；学生看不到 AI 状态、参考答案、草稿或未确认成绩，异常原文不出现在教师响应中。
4. 未登录重试返回 401，学生和其他教师返回 403。本班教师与管理员同时发起相同版本重试，只有一次 202，另一次 409。
5. 实际等待人工重试的基础退避后，第四次执行成功，AI 草稿总分 15，人工成绩仍为空。
6. 教师明确给分 9 + 4，最终成绩 13；学生两个查分入口一致。再次确认或重试均返回 409。
7. OpenAPI 包含 retry-grading 的请求模型、必填 expected_retry_count 和主要错误响应。

此场景真实运行 worker 的轮询循环，但用测试 provider 注入故障；没有调用真实模型或外部服务。

### Worker 进程中断与重启

另一次独立测试同样通过 HTTP 建班、出题、发布和提交。启动实际子进程，通过生产入口初始化数据库并领取任务，测试 provider 暂停在评分阶段。HTTP 观察到 processing 后终止该子进程，再使用正常 `python -m app.worker` 启动新进程。

实际等待旧租约到期及恢复退避后，同一提交由新进程接管并生成占位草稿，累计执行次数为 2，未开启手动重试轮次。学生答案全程保留，人工确认后两个查分入口均返回 8 分。测试没有直接修改任务状态、租约或等待时间。

测试配置将整份超时设为 1 秒、租约 2 秒、退避基数 1 秒，以避免长时间等待；不修改开发 `.env` 或生产默认值。进程中断发生在 provider 完成之前，不等同于机器断电或数据库崩溃演练。

