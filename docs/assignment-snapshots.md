# 作业题面与快照：节点 08

节点 08 已实现新建已发布作业的题目快照、学生完整题面、教师/学生响应分离，以及提交评分和教师确认使用同一数据来源。节点 09 已补充 [草稿编辑、独立发布/归档及截止时间处理](assignment-lifecycle.md)，仍未接入真实 AI。

## 快照保存时机

当前 `POST /api/v1/assignments` 支持 `status=published`（默认）或 `draft`。

- published：验证班级、题目归属及活动状态，沿用 07b 原子锁题；锁成功后重新读取题目内容，按请求中的题号顺序创建快照，再将整个作业一次写入 MongoDB。
- draft：保留题目 ID，不存发布快照，仅向教师/管理员提供题面预览。草稿沿用 07b 锁题策略；使用节点 09 的 publish 接口正式发布并冻结，不能通过直接改数据库 status 代替发布。

存储结构在 `Assignment.questions[]` 中保留 `question_id`，增加 `snapshot`：题干、参考答案、满分、评分标准、图片 URL 列表。已发布新作业记录 `snapshot_version=1`，题号顺序由数组顺序决定。客户端不能传 snapshot、snapshot_version 或其他额外字段，返回 422；重复题目 ID 返回 400，防止答案与评分对应不明确。

锁后重新读取是必要的：若题目编辑在取得锁之前成功，新作业应保存更新后的内容，而不是初次查询时的旧副本。沿用单文档锁协议，不依赖副本集事务；锁或作业保存失败仍可能留下保守锁，见 [题库文档](questions.md)。本轮不自动解锁或放宽已引用题目的编辑限制。

## 响应契约

创建作业返回教师视图。`GET /assignments/my` 和 `GET /assignments/{assignment_id}` 根据已认证角色返回不同模型：

| 字段 | 学生 | 教师/管理员 |
| --- | --- | --- |
| view | student | teacher |
| question_source | 数据来源标记 | 数据来源标记 |
| questions[].question_id | 原题 ID，用于提交答案 | 同左 |
| questions[].position | 从 1 开始的题号 | 同左 |
| questions[].prompt | 题干 | 同左 |
| questions[].image_urls | 图片 URL 列表 | 同左 |
| questions[].max_score | 满分 | 同左 |
| questions[].reference_answer | 不存在此字段 | 参考答案 |
| questions[].rubric | 不存在此字段 | 评分标准，可为 null |

作业 ID、标题、描述、班级、截止时间、状态、创建人和创建时间字段保留。列表仍是数组，不在本节点引入作业分页。学生题目项示例：

```json
{
  "question_id": "507f1f77bcf86cd799439011",
  "position": 1,
  "prompt": "简述数据库索引的作用。",
  "image_urls": [],
  "max_score": 10
}
```

学生响应通过独立字段白名单构造，不返回内部 snapshot、参考答案或 rubric，不是返回 null 来隐藏字段。OpenAPI 使用 view 区分两种模型；传入 `?view=teacher` 不会改变当前用户角色或结果。

学生只看自己班级的 published 作业；草稿和归档作业不出现在列表，详情和提交返回 404。跨班或其他教师访问返回 403。归档后的历史提交与教师确认仍可访问，规则见节点 09 文档。

## 数据来源与旧作业兼容

`question_source` 明确区分：

| 值 | 含义 |
| --- | --- |
| snapshot | 新版已发布作业的完整 v1 快照，不读取题库补内容 |
| draft_preview | 草稿读取当前引用题目，仅供教师/管理员预览，不代表已发布 |
| legacy_reference | 没有快照的旧已发布作业，读取其受保护的题目引用，不宣称是当年发布内容 |

归档后保留上述来源；归档草稿仍为 draft_preview，归档的已发布快照仍为 snapshot，不因状态变化失去批改依据。

旧文档缺失新字段时仍可读取；不自动回写或批量迁移旧作业，不把当前题库数据伪造成历史快照。旧题如在更早时期已被外部改过，无法据此恢复真正发布时的内容。旧引用的原题即使已经停用，也仍可用于历史读取和批改；新作业仍不能选用停用题。

旧引用缺失题目、快照缺项、版本缺失但存在快照或版本不支持时，相关请求返回 409，要求检查数据。声明为 v1 的作业绝不回退到当前题库填空，否则可能悄悄改变批改依据。列表中可访问作业存在这类问题时，整个列表请求会报错，不静默丢弃该作业。

本轮保留 07b 对旧引用和内容锁的保护。所有写入仍需使用新入口，不混跑旧版应用写同一数据库；不提供强制解锁或自动修复/迁移接口。

## 提交与批改

提交使用作业题目 ID 对应答案；`GradingService` 现在接收独立 `QuestionSnapshot` 内容对象，而非题库数据库文档。新已发布作业按冻结参考答案、rubric、满分和题面传入评分器；教师确认的分数上限也由同一份快照决定。

已发布作业不因源题改名、改分、停用或删除而丢失题面/批改依据。测试直接模拟这些外部变动以验证独立性，正常题库接口依旧遵守 07b 锁规则。复制的是图片 URL，不是图片文件本身，不能保证远端图片资源不会被替换或删除。

关键词占位算法不变，尚无真实模型语义评分。节点 11 已补独立学生提交响应，未确认成绩隐藏，确认后也不返回 AI 草稿字段；首次确认后锁定，见 [批改说明](teacher-review.md)。
