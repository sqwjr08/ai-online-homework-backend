# 提交正确性：节点 10

## 一次正式提交

`POST /api/v1/assignments/{assignment_id}/submissions` 仅学生可用，沿用节点 09 的本班、已发布、班级活动状态和 UTC 截止检查；评分后保存前再次检查。成功返回 201，重复提交返回 409，不覆盖原答案或成绩，不支持重交。

数据库新增 `unique_assignment_student` 联合唯一索引，键为 assignment_id、student_id。请求开始的重复查询用于提前返回，最终并发正确性依靠数据库索引：两个请求同时通过查询，也只能插入一份提交，另一个映射为 409。不同学生可以提交同一作业，同一学生可以提交不同作业。

评分仍在答案保存前同步执行，竞争请求可能重复评分；失败或超时也可能阻止保存。唯一索引不等于评分任务去重或跨集合事务。异步评分、失败重试由节点 14 完善，归档与插入的短暂跨集合竞态限制不变。

## 答案校验

- answers 至少一项，每项仅接受 question_id 和 answer_text；顶层只接受 answers。传入学生 ID、状态或分数字段返回 422。
- answer_text 为非空白字符串，长度 1 至 20,000 字符；保留合法文本原始空格、换行，不自动重排格式。纯空白、空字符串、超长或 null 返回 422。
- 必须恰好覆盖作业全部题目，每题一次；重复、遗漏或多余题目返回 400。答案顺序可以不同于作业题号，按 question_id 对应。
- 异常旧作业的空题目列表或重复题目返回 409，需要单独维护；不生成空提交。
- 输入不合法时不会进入评分或新增提交。节点 11 已补充 [教师确认、成绩锁定和学生结果隔离](teacher-review.md)。

## 找回本人提交

新增 `GET /api/v1/assignments/{assignment_id}/submissions/my`，只接受学生身份。按“作业 ID + 当前认证学生 ID”查询，不接受指定其他学生参数；有记录返回 200，无本人记录返回 404（不会泄露其他学生是否提交）。未登录 401，教师/管理员 403。

该入口用于重复提交后的找回、刷新页面及历史查询。不依赖作业当前可见性，作业/班级归档、当前不再属于原班级均不抹去本人的历史记录；与原按 submission_id 查询的所有权规则一致。

节点 11 已改为独立 StudentSubmissionRead：未确认时隐藏最终分数和评语，确认后可见最终结果，始终不返回 AI 草稿字段。教师首次确认后锁定，不提供更正入口，见 [批改说明](teacher-review.md)。

## 旧数据与索引

启动时在 Beanie 初始化索引前，只读检查 submissions：作业/学生 ID 必须为 BSON ObjectId，且不能存在重复组合。发现异常时抛出明确的 `Submission index blocked` 错误，拒绝继续初始化，不自动删除、合并记录或删旧索引。

已有数据的部署应先备份，并在停止写入的维护窗口启动新版本。出现检查错误时由维护者明确核对和修复冲突，再重启；不要删除集合来绕过检查。检查后如果仍有外部并发写入，最终唯一索引创建也会拒绝重复数据。已有冲突索引配置同样可能导致启动失败，仍需人工处理。

本轮只在独立测试数据库验证旧数据情景，未访问或修改原开发数据库。无需批量迁移正常记录，不升级依赖。
