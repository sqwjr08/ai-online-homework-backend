# 简答题题库：节点 07

07a（创建校验、详情、搜索分页）和 07b（部分编辑、停用、引用保护）均已完成。本节点不引入课程模型、真实 AI 或题面快照；旧题目缺失新增的内部锁字段时按 false 读取，不批量迁移开发数据。

## 当前接口

统一前缀 `/api/v1`，仅教师和管理员可访问。教师只操作自己创建的题目，管理员可访问全部；学生不能访问任何题库接口，以免泄露参考答案和评分标准。

| 方法与路径 | 行为 |
| --- | --- |
| POST /questions | 创建简答题，服务端填写创建人、启用状态和时间 |
| GET /questions/{question_id} | 题目详情；拥有者和管理员可读取已停用题目 |
| GET /questions | 搜索和分页，默认只返回启用题目 |
| PATCH /questions/{question_id} | 部分编辑未停用、未引用且未锁定的题目 |
| POST /questions/{question_id}/disable | 停用未引用、未锁定题目；重复停用幂等 |

详情不存在返回 404，其他教师访问返回 403，非法 ObjectId 返回 422。匿名访问返回 401，学生访问返回 403。

## 创建校验

| 字段 | 规则 |
| --- | --- |
| prompt | 必填文本，去除首尾空白后 1 至 10000 字符 |
| reference_answer | 必填文本，去除首尾空白后 1 至 20000 字符 |
| max_score | 必填、有限、严格大于零的 JSON 数值；允许小数，不接受布尔值或数字字符串 |
| rubric | 可省略或为 null；提供文本时去除首尾空白后 1 至 5000 字符 |
| image_urls | 沿用字符串列表，默认空数组；本轮不新增图片上传或 URL 安全校验 |

文本内部的换行、缩进保留。拒绝空白题干、参考答案或评分标准；拒绝创建请求中的未知字段以及创建人、启用状态、ID、时间等服务端字段，返回 422，且不写入题目。

评分标准仍是教师自定义文本，不解析评分项、不校验分值加总，也不验证语义正确性。当前关键词占位评分器不使用 rubric 推理；这些校验不能等同于真实模型评分质量保障。满分没有新增固定上限，教师仍可自定义。

## 搜索与分页契约变更

`GET /questions` 从数组改为分页对象：

```json
{"items": [], "total": 0, "page": 1, "page_size": 20}
```

- `page`：默认 1，范围 1 至 1000000。
- `page_size`：默认 20，范围 1 至 100。
- `q`：最多 200 字符，去除首尾空白后按题干做不区分大小写的子串查询。省略、空字符串或纯空白表示不搜索。
- 搜索内容按字面量转义，`.*`、`[` 等不是可执行的正则表达式；不搜索参考答案或评分标准。
- `is_active`：默认 true，仅启用；传 false 仅停用。
- 先按权限及状态筛选再计数、分页，按 `created_at`、`_id` 倒序排列。同一时间创建的题目也有稳定次序；跨请求遇到并发新增时，偏移分页不保证固定快照。
- 超出最后一页返回空 items，total 保留筛选后的总数。

查询示例：`GET /api/v1/questions?q=索引&page=1&page_size=20&is_active=true`。

题目响应新增 `is_active`、`updated_at`，其余题干、参考答案、rubric、图片、满分、创建人字段保留。现有时间字段沿用数据库 UTC 存储行为；MongoDB 以毫秒保存，读取后可能不带时区后缀，创建响应的内存时间可带更高精度。本轮未做跨模块时间序列化重构。

## 虚构示例

[questions.json](examples/questions.json) 包含 3 道自拟演示题：数据库索引、密码存储、并发入班。文件是三个创建请求对象的数组；调用 POST 时每次发送其中一个对象，不是批量导入接口。

示例只存于文档，测试验证其符合请求模型；不会自动写入开发数据库，无需上传真实题目。参考答案与评分标准用于演示接口格式，不代表真实 AI 已能按规则批改。

## 部分编辑与停用

PATCH 只接受 `prompt`、`reference_answer`、`max_score`、`rubric`、`image_urls`，沿用创建校验。省略字段保持原值；`rubric: null` 清除评分标准，`image_urls: []` 清除图片引用，但不删除图片文件。必填内容字段及 image_urls 不接受 null，空对象或注入归属、状态、内部锁、时间字段返回 422。

```json
{"prompt": "简述数据库索引的作用。", "rubric": "说明查询效率收益得满分。"}
```

编辑仅对提供的字段执行数据库 `$set`，更新 `updated_at`，保留创建人、创建时间、状态和未提供字段。并发修改不同字段不会互相覆盖；同一字段采用最后成功写入的值，尚无面向客户端的版本冲突检测。

停用接口无需请求体，只置 `is_active=false` 并更新时间，不物理删除题目。重复或并发停用返回 200，已停用题目不再更新时间。停用后仍可读取详情、在停用列表中查到，但编辑返回 409，不能加入新作业。本轮不提供恢复启用或永久删除。

两种操作都先检查教师归属；管理员可维护他人题目，但不能绕过引用保护。匿名 401、学生/其他教师 403、非法 ID 422、不存在 404、不可修改状态 409。

## 作业引用保护与并发边界

07b 在没有快照时建立的保守保护仍保留：无论草稿还是已发布作业，只要引用了题目，其内容及启用状态都禁止更改，返回 409；需要修改时按新内容创建另一道题。节点 08 为新已发布作业保存独立快照，旧作业的作答和教师确认继续使用原题，不自动迁移或解锁。

为避免仅“先查引用再更新”的竞态，Question 新增内部字段 `content_locked`，默认 false，不是请求可编辑字段，也不作为当前题目响应字段。作业入口先完成归属/活动状态校验，再逐题原子设置锁，最后写入作业。编辑/停用的原子更新条件同时要求题目启用且锁不为 true。

- 作业先取得锁：后续编辑/停用返回 409，即使它此前已查到“未引用”。
- 编辑先成功：随后创建的作业使用更新后的题目，锁住后不再变化。此策略不检测教师先前打开页面时看到的旧版本。
- 停用先成功：新作业的锁定检查返回 409，不写入引用停用题目的作业。
- 老作业没有锁字段：编辑/停用前查询已有引用，发现后补内部锁并拒绝操作。无引用的旧题目仍可编辑。
- 已锁定题目仍可供其他作业复用。锁定本身不更改题目内容、活动状态或内容更新时间。

这是兼容单机 MongoDB 的保守保护，不是跨集合事务。多题锁到一半失败、作业插入失败或进程中断，可能留下尚未被成功作业引用的锁；不会自动解锁，因为另一个并发作业可能已依赖它。可重新用原题创建作业，或需要编辑时新建题目；本轮不提供强制解锁。

删除作业不会自动解锁。归档班级也不会放开其作业题目。保护要求所有相关写入使用新入口；直接改数据库、混跑旧版本写入同一数据库会绕过协议，不在本轮保证范围。上线前需确定唯一写入入口。
