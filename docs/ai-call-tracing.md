# AI 调用日志

正式 worker 使用百炼时，每次评分调用结束写入一行 JSON，位置为工作目录下 `.logs/ai-calls.jsonl`。占位评分不生成模型调用日志。无需新增服务、数据库集合或查询接口，学生接口不增加字段。

记录 UTC 开始时间、耗时毫秒、配置模型名、provider、HTTP 状态、供应商请求 ID、输入/输出 token、成功/失败/取消状态及固定错误码。worker 额外提供内部 submission_id、question_id 和累计 attempt，便于关联作业及重试。直接调用适配器时可能没有任务关联信息。

请求 ID 优先来自 x-request-id 响应头，兼容响应 request_id 字段；缺失记 null，不把响应的 completion id 当成供应商请求 ID。用量取响应 usage.prompt_tokens/completion_tokens，仅接受非负整数；缺失、超时、无效值均记 null，不当成 0。解析评分失败时仍保留已经获得的合法用量。日志不计算金额，实际费用以百炼账单为准。

不记录 Key、Authorization、账号身份、题干、参考答案、学生答案、模型回复或异常原文。请求 ID 有字符及长度约束；日志字段采用白名单。内部任务 ID 也属于后台数据，不应公开提交或暴露给学生。

默认单文件 5 MiB，保留 3 个历史文件，合计约 20 MiB。当前文件轮转适用于一个 worker 进程；多进程部署需分开工作目录，或改用集中日志采集，不能让多个进程共写同一轮转文件。`.logs/` 已被 Git 忽略，不上传。

日志目录创建失败会阻止 worker 启动，需修复目录权限；运行中写入失败不会改变评分结果或触发重试，但可能丢失记录。进程强制终止也可能缺少最后一条日志，因此这不是可靠计费账本。任务总超时对内部调用的取消会记 cancelled，整份提交状态仍由 worker 的 timeout 策略处理。

测试仅用 MockTransport 和临时目录，不调用真实模型；验证元数据、敏感内容排除、失败/取消/未知用量、轮转及写入失败不向评分流程抛异常。日志能力不改变现有批改与教师确认规则。
